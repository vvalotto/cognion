# Plan de Implementación: US-10.2.2 - Instalación en servidor Linux con Docker, respaldo mínimo y guía única

**Patrón:** clean-architecture-bc · **Producto:** cognion · **Capa:** despliegue (`deploy/servidor/`, `docs/`), sin código de aplicación

## Diseño
`deploy/servidor/` parte del lado servidor de `deploy/gcp/` (que no usa `gcloud`) y suma configurabilidad, el respaldo y la variante sin dominio. Los scripts de Google no se copian.

```
deploy/gcp/ (no cambia)                     deploy/servidor/ (nuevo, sin gcloud)
  docker-compose.yml  ── generaliza ─────►    docker-compose.yml   (memoria y puertos configurables)
  Caddyfile           ── igual ──────────►    Caddyfile
  cognion.sh          ── + respaldar/restaurar, chequeo de Docker, url_base ─► cognion.sh
  salud.sh · preparar-env.sh · .env.example ─► (adaptados)
  aprovisionar/desplegar/destruir/preparar-vm  ✗ (son de gcloud/Debian)
                                              + respaldar.sh · restaurar.sh
docs/INSTALACION.md (nuevo, lo lleva el paquete) · CLAUDE.md y fly.toml (limpieza)
```

## Componentes a Implementar

### 1. `deploy/servidor/`
- [ ] `docker-compose.yml`: `db`, `app`, `caddy`; `mem_limit` por `COGNION_MEM_DB`/`COGNION_MEM_APP`; puertos de Caddy por `COGNION_HTTP_PORT`/`COGNION_HTTPS_PORT` (80/443 por defecto); solo Caddy publica puertos.
- [ ] `Caddyfile` igual al de GCP; `.env.example` con marcadores; `preparar-env.sh <dominio> | --sin-dominio <host>` (imagen de `VERSION`, secretos distintos por corrida, 600, no pisa un `.env`).
- [ ] `cognion.sh`: subcomandos de GCP + `respaldar`, `restaurar`; chequeo de `docker` y `docker compose`; `url_base` para `estado` con o sin dominio; textos que dicen `deploy/servidor`.
- [ ] `salud.sh` igual al de GCP.

### 2. Respaldo mínimo
- [ ] `respaldar.sh`: `pg_dump -Fc` por `docker compose exec -T db`, verificación (`pg_restore --list`), `sha256`, rotación (`COGNION_RESPALDOS_N`, 30), sin archivos a medias si falla.
- [ ] `restaurar.sh <archivo> [--reemplazar]`: valida hash y lectura; ensayo en base temporal por defecto; `--reemplazar` con confirmación `RESTAURAR`, deteniendo y levantando la aplicación.

### 3. Guía y limpieza
- [ ] `docs/INSTALACION.md` con las secciones de la spec (incluye el cron del respaldo y la advertencia de no usar `localhost`).
- [ ] `CLAUDE.md`: fila de hosting y despliegue; `fly.toml`: comentario de histórico.

## Tests (Fases 4 y 7)
- **Estructura** (`tests/unit/inc10/test_us_10_2_2_servidor.py`): sin `gcloud`; compose (servicios, puertos y memoria configurables, base interna); `Caddyfile` idéntico al de GCP; `.env.example` con marcadores; el paquete incluye `deploy/servidor/` y `docs/INSTALACION.md`.
- **`preparar-env.sh`**: permisos 600, secretos distintos, dominio, imagen de `VERSION`, no pisa, dominio inválido, `--sin-dominio`.
- **`cognion.sh` con `docker` simulado** (reutiliza `_simuladores.py`): Docker ausente, `iniciar`, `migrar`, `estado` con y sin dominio, `desplegar` con respaldo previo (y abortando si falla), `rollback`.
- **`respaldar.sh` y `restaurar.sh` con `docker` simulado** (ampliar el simulador con `exec`/`pg_dump`/`pg_restore`): generación y `sha256`, rotación, fallo sin dejar archivos, hash corrupto, ensayo, `--reemplazar` y su confirmación.
- **Guía** (`docs/INSTALACION.md`): secciones obligatorias y que cada orden `cognion.sh <subcomando>` que menciona existe.
- Suite unitaria completa, mypy, ruff, black, `lint-imports`, DesignReviewer; `bash -n` a todos los scripts.

## Riesgos
- **No hay Docker en este equipo:** el compose y los scripts se verifican por estructura y con `docker` simulado; el comportamiento real se confirma en el Issue #624 (pendiente) (servidor Linux). El reporte lo dice.
- **Duplicación con `deploy/gcp/`:** se acepta para no tocar un camino ya verificado; un test iguala `Caddyfile` y `salud.sh` para detectar deriva. Unificarlos queda como mejora.
- **`sha256sum` vs. `shasum`:** los scripts usan `sha256sum` (Linux); el simulador de los tests lo provee.
- **`respaldar.sh` crece el disco:** rotación por cantidad; la guía recomienda copiar los respaldos fuera del servidor.
