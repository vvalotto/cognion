# Plan de Implementación: US-10.2.1 - Versión única 1.0.0 y paquete de release

**Patrón:** clean-architecture-bc · **Producto:** cognion · **Capas:** `shared/frameworks` (lectura de la versión), `app` (endpoint), y tooling (`scripts/`, `.github/workflows/`, `Dockerfile`)

## Diseño
Un archivo `VERSION` en la raíz es la única fuente. El resto lo lee o lo verifica contra él.

```
VERSION (1.0.0) ─┬─► src/shared/frameworks/version.py ──► FastAPI(version=...) y GET /api/health
                 ├─► guarda de test: pyproject.toml, frontend/package.json, FastAPI
                 ├─► Dockerfile (COPY VERSION)
                 └─► cd.yml: tag vX.Y.Z == VERSION ─► scripts/extraer_notas.sh + scripts/empaquetar_release.sh ─► gh release create
```

## Componentes a Implementar

### 1. Versión
- [ ] `VERSION` con `1.0.0`; `pyproject.toml` y `frontend/package.json` a `1.0.0` (y `frontend/package-lock.json` si repite la versión del paquete).
- [ ] `src/shared/frameworks/version.py`: `obtener_version() -> str` (lee `VERSION`, sin espacios; falla claro si no existe), con docstring.
- [ ] `src/app.py`: `FastAPI(version=obtener_version())`; `/health` devuelve `{"status": "ok", "version": ...}`.
- [ ] `Dockerfile`: `COPY VERSION ./`.

### 2. Paquete y Release
- [ ] `scripts/extraer_notas.sh <X.Y.Z>`: imprime la sección de `CHANGELOG.md` de esa versión; sale con error si no existe o está vacía.
- [ ] `scripts/empaquetar_release.sh <X.Y.Z>`: arma `dist/cognion-X.Y.Z-instalacion.tar.gz` desde una lista de archivos (`VERSION`, `CHANGELOG.md`, guía y `deploy/servidor/` cuando existan); falla si un archivo obligatorio falta.
- [ ] `.github/workflows/cd.yml`: en tags, verificar tag == `VERSION`, armar el paquete y las notas, y `gh release create` con `permissions: contents: write`; no publicar `latest`.
- [ ] `CHANGELOG.md`: sección `[1.0.0]` en `Unreleased` hasta el cierre.

## Riesgos
- **El CD no se prueba localmente:** el paso de Release se valida recién con el primer tag; por eso la lógica vive en scripts probados y el workflow solo los llama.
- **El tag `v1.0.0` publicará una imagen real:** esta US no lo aplica; se hace en el cierre (`BL-016`).
- **Cambio de `/api/health`:** aditivo (el código y `status` no cambian); healthcheck de Docker y Caddy siguen funcionando.
